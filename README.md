# ONCE 一次性商店

一个看起来完全正常的购物网站，但**每一个 URL 只能访问一次**。

首页 `/` 是店里唯一不会被烧掉的地址：它每次都会撕一张新票，把你在 302 里送到一个随机地址。
那张票在你打开它的瞬间就被用掉了。刷新、后退、收藏、把链接发给朋友——都会得到 404。

```bash
npm start          # 或 node server.js
open http://localhost:4173/
```

无依赖，只要 Node 18+。端口用 `PORT=8080 node server.js` 改。

---

## 它是怎么跳的

```
GET /                    302 → /go/9fK2xQ7mPz        ← 发一张新票
GET /go/9fK2xQ7mPz       200 → 首页 HTML              ← 票在渲染前就被烧掉
GET /go/9fK2xQ7mPz       404 → "这张票已经用过了。"    ← 同一个地址再也打不开

GET /go/LJWi1yJrBuaq     200 → main.css（一次性）      ← 页面里的 CSS 也是一张票
GET /go/LJWi1yJrBuaq     404
```

- 票 = `crypto.randomBytes(9)` 的 base64url，服务端内存里的 `Map`，命中即删。
- 保持存活但没被用过的票 20 分钟后也会过期。
- 被用掉的票会留一条"墓碑"，所以 404 能诚实地区分「用过了」和「没这张票」。
- 页面渲染时才给 CSS / JS / favicon / 每个商品图 / 每个链接**现场发票**，
  所以每次加载的 URL 全都不一样——连图片地址都在跳。
- 所有响应都带 `Cache-Control: no-store`，后退会真的再发一次请求，于是撞上已经烧掉的票。
- 万一浏览器用 bfcache 恢复了页面，页内 JS 会在 `pageshow` 时强制 `reload()`，结果一样是 404。

## 店里的页面

| 地址 | 内容 |
| --- | --- |
| `/` | 唯一的稳定入口，发一张首页票 |
| `/go/<t>` → home | 首页：主推、分类、宣言 |
| `/go/<t>` → cat:table / travel / clean / digital / all | 分类列表 |
| `/go/<t>` → product:<sku> | 商品详情 + 相关推荐 |
| `/go/<t>` → cart | 购物袋（存在 cookie 里） |
| `/go/<t>` → add / remove / checkout | 一次性动作票，消费后 302 到**新的**购物袋地址 |
| `/go/<t>` → about | 关于这家店 |
| 其它任何东西 | 404 |

每个页面右下角有一张票根，写着「第 N 跳」和当前票号；N 存在 cookie 里，
所以你能看见自己在店里跳了多远。

## 文件

- `server.js` — 发票 / 烧票 / 路由 / cookie
- `render.js` — 全部 HTML、CSS、JS 和商品插画（服务端生成 SVG，所以图片也能一次性）
- `data.js` — 8 件商品和 4 个分类

## 想改的话

- 加商品：往 `data.js` 的 `PRODUCTS` 里加一条，`art` 用 `render.js` 里已有的形状或新写一个。
- 票的有效期：`server.js` 的 `TTL`。
- 想要更疯：在 `dispatch()` 里让页面票再 302 一次，一跳变两跳。

## 已知的、故意保留的后果

- 分享链接给朋友 = 你自己打不开；朋友打开后你也打不开。
- 页面里任何东西二次加载都会 404（这正是要点）。
- 返回上一页 = 404 页面，而 404 页面本身也是新的一张票。
- 店是假的，不会发货。
